## 구현 및 활성화

실제 상담 접수, 서버 저장·중복 방지, 가격·옵션·동의 스냅샷, 관리자/상담자 권한, HttpOnly 세션·CSRF·속도 제한, 접수함·배정·상태·메모·감사 이력, 직원 생성/중지, 카탈로그 초안/게시·패키지·순서·판매중지, WebP 사진 관리, 주중/주말/특정일 가격, 선택 옵션의 서버 합산, 장소 안내를 구현했습니다.

2026-11-01 사용자의 비상업용 공개 지시에 따라 접수를 열었습니다. 처리 주체는 모먼트링크 운영팀, 문의는 1833-8047, 보유기간은 접수 후 30일입니다. 신규 운영 정책이며 법률 검토 인증을 의미하지 않습니다. 관리자에서 수정 가능하고 정책 수정 시 동의 버전 변경이 필요합니다. 만료 즉시 조회 차단, 매일 정리, 본인 삭제 요청의 관리자 처리를 지원합니다. 기존 접수는 동의 당시 보유기한을 유지합니다.

알림 outbox·안전 재시도·SOLAPI 결과 조회·웹 푸시 구독·접수 상세 이동을 구현했습니다. 무료 VAPID 키 및 서버 푸시는 ON, 실제 기기의 알림 권한/수신은 미검증입니다. SMS 실발송과 OPS 자동 쓰기는 OFF입니다.

## 아직 완료되지 않은 항목

BOATN/KHT/설렘의 실제 예약 등록·변경·취소 연동은 운영 API 계약과 전용 인증이 확보되지 않아 미완료입니다. 로컬 BOATN 개발 계약은 예약 권한이 false이며 기존 PWA의 설렘 연결도 로컬 검증 기록입니다. 이를 운영 연결로 승격하지 않았습니다. 기존 운영 코드·DB·예약은 변경하지 않았습니다.

실제 상품 사진, 미확정 가격/주소는 임의 생성하지 않았습니다. 물리 iOS/Android의 설치·푸시·문자 앱 전달은 미검증입니다. 문자 실발송은 사용자 보류 조건과 공급자 설정이 남아 있습니다.

## 실행

Node.js 24, pnpm 11.25.0. pnpm install --frozen-lockfile, pnpm run check, pnpm test, pnpm run build.

PowerShell에서 LOCAL_SYNTHETIC=true와 LOCAL_TEST_PASSWORD(개별 로컬 전용 8자 이상)를 환경변수로 설정한 뒤 pnpm dev를 실행합니다. http://127.0.0.1:4173 의 local-admin은 입력한 비밀번호로 로그인하는 메모리 합성 DB 전용 계정입니다. 운영 비밀번호를 재사용하지 않으며 Vercel에서는 이 모드를 사용하지 않습니다.

전용 운영 DB 초기화: MOMENT_LINK_DATABASE=true로 scripts/migrate.mjs 실행. 현재 스키마 2까지 적용됐고 RUN_DB_MIGRATIONS=false입니다. 실제 키는 Git에 올리지 않습니다.

최초 관리자 정보는 작업 PC .local/owner-credentials.json에만 있으며 Git/공개 정적 출력에서 제외됩니다. 비밀번호 변경 시 기존 자기 세션은 회수됩니다.

## PWA 설치

고객 화면 아래의 **모먼트링크 앱 설치**, 또는 관리자 상단 **앱 설치**에서 시작합니다. Chrome/Edge에서 설치가 지원되면 기본 설치 창으로 연결하며, 지원하지 않는 브라우저에는 기기별 안내가 표시됩니다. iPhone/iPad에서는 Safari의 공유 → 홈 화면에 추가 후 설치한 앱으로 엽니다.

관리자는 설치한 앱에서 로그인한 뒤 **문자·알림 → 이 기기 푸시 구독**으로 알림을 허용합니다. 설치 자체가 푸시 권한을 허용하지는 않습니다. 앱 아이콘과 알림에는 기존 모먼트 로고에서 만든 PNG/단색 badge를 사용하며, 알림 모양은 OS·브라우저에 따라 다를 수 있습니다.

첫 온라인 방문 후 공개 앱 화면만 오프라인에서 열 수 있습니다. 상담 접수·로그인·관리자 업무·사진은 인터넷 연결이 필요합니다. API 응답과 고객 정보는 서비스 워커 캐시에 저장하지 않습니다. 실기기 설치·수신 검증은 별도로 필요합니다.

플랫폼 아이콘은 scripts/app-icons.mjs가 빌드와 로컬 개발 시 assets/icon.svg에서 생성합니다. 테스트: node --test tests/server.test.mjs tests/pwa.test.mjs.

## 고객별 4단계 문자 안내

관리자 **상담 접수함 → 고객 번호 · 문자 안내**에서 예약 접수·금액 안내 / 결제 후 예약 확정 / 하루 전 안내 / 이벤트 후 안부를 선택합니다. 고객과 협의한 날짜·시간·최종 금액·장소를 확인하고 **저장하고 문자 준비 → 고객 번호 · 문자 앱 열기**를 누릅니다. 문자 앱의 마지막 전송은 담당자가 직접 합니다. 본문 입력이 지원되지 않는 기기와 PC에서는 **문구 복사**를 사용합니다.

요트·출장·트렁크·헬기와 선택한 패키지에 맞춰 문구가 생성됩니다. 결제 후 확정·하루 전 안내에는 일정·장소 확정 및 입금 확인이 필요합니다. 일정·금액 변경 시 확인 체크가 해제되고 문구가 다시 생성됩니다. 문구는 고객별 수정·저장이 가능하며, 문자 앱 열기 요청과 담당자의 발송 확인을 구분해 기록합니다. 자동 예약 발송·입금 자동 조회·수신 확인 기능은 아닙니다.

스키마 3은 상담에 비공개 `communication` 컬럼을 추가합니다. 권한·CSRF·버전 충돌 검사를 적용하고 기존 보유기한에 따라 함께 삭제합니다. 초기 관리자 생성은 직원 계정이 전혀 없는 DB에서만 실행하므로 관리자 이름 변경 후 재마이그레이션해도 초기 계정이 재생성되지 않습니다. 테스트: `node --test tests/server.test.mjs tests/pwa.test.mjs tests/messages.test.mjs`. 상세: [문자 안내 운영 설명](docs/CUSTOMER_MESSAGES.md).
