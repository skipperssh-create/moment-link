# 예약 확정 문자와 승선신고·보딩패스 연결

2026-11-11 배포 작업본. Work의 로컬 브라우저 사용이 꺼져 있어 화면 검수를 진행하지 못했다. 이 한계를 안내한 뒤 사용자가 ‘배포해’라고 명시하여 이번 배포를 진행한다. 브라우저·실기기 검수를 완료했다고 주장하지 않는다. 최종 배포 결과와 버전은 로컬 배포 기록을 확인한다.

## 담당자 사용 순서

1. 요트 예약을 확정하고 BOATN OPS 등록 완료를 확인한다.
2. 상담 상세 → 문자 안내 → 결제 후 예약 확정 → 문자 준비를 누른다.
3. 기존 확정 문자 아래에 최신 OPS 승선신고·보딩패스 링크가 한 번 들어간다.
4. 문자 앱을 열어 담당자가 전송한다.
5. 실제 전송 후 발송 기록을 누르면 OPS 예약의 고객명 옆에 ‘승선 안내 · 모먼트 발송 확인’, 담당자, 한국 시간 기준 시각이 표시된다. 이미 열린 OPS 목록에서는 새로고침한다.

발송 기록은 담당자의 수동 확인이다. 문자 앱을 열거나 내용을 복사한 것만으로 발송 완료를 기록하지 않으며, 통신사 전달·고객 수신을 확인했다고 표시하지 않는다. 자동문자 설정과 유료 발송 서비스는 변경하지 않았다.

고객은 기존 OPS 화면에서 필수 안내·동의를 확인하고 승선신고서를 작성한다. 기존 보딩패스 발급 조건, 명단, QR, 동의는 유지된다.

## 계약과 보존

- OPS의 기존 Bearer 인증과 외부 참조 조회 아래에 읽기 전용 `GET bookings/by-reference/:reference/boarding-pass`를 추가한다. 해당 참조로 이미 연결된 예약의 고객용 링크만 반환하며 검사자 토큰은 반환하지 않는다.
- 모먼트링크는 예약 상태·OPS 성공 상태·예약 ID·연락처·일정·인원·URL 출처를 확인한다. 확정 문자 준비 때 최신 링크를 붙이고 문자 열기 기록·발송 확인 때 다시 확인한다.
- 변경된 초대 링크/연락처/일정/인원, 취소·노쇼·만료, OPS 충돌·오류 상태에서는 안내를 차단한다. 실패는 자동 재시도하지 않는다.
- 발송 확인은 기존 상담의 비공개 communication에 저장한다. 최근 문자 이력 40개 제한과 별도로 최신 승선 안내 확인 기록을 보존한다.
- OPS는 기존 서명된 상담 상태 조회 응답으로 발송 확인을 읽고 현재 예약의 초대 정보 해시와 비교한다. 오래된 안내를 현재 예약의 발송 완료로 표시하지 않는다. 이 조회는 예약·입금·명단·캘린더 또는 OPS 작업을 변경하지 않는다.
- 기존 예약/충돌 건의 재처리·일괄 수정·이력 소급 생성은 하지 않았다. 기존 공개 DB 스키마 변경도 없다.

## 검증 상태

- 모먼트링크 전체 185개 검사 통과, 마지막 보존 변경 후 관련 22개 검사 재통과. 문법 검사 및 정적 빌드 통과.
- OPS 전체 3,268개 검사 및 TypeScript 통과. 마지막 충돌 방어 변경 후 관련 2개 검사 재통과. 로컬 Vinext 빌드 통과.
- 가상 PGlite/SQLite 데이터로 중복 링크, 다른 고객·일정·인원, 취소·충돌 보호, 담당 권한, 수동 확인과 문자 열기의 구분, 이력 제한 이후 확인 보존을 검증했다.
- 실제 고객 문자/푸시, 실제 예약 수정, 운영 캘린더·OPS 충돌 변경: 0건.
- 실제 브라우저·8개 viewport·실기기 검증: 미실시. 브라우저 연결 복구 후 확인해야 한다.

OPS 작업 경로는 `../boatn-ops-boarding-pass/.sites-checkout`이다. 이 체크아웃은 Sites 원본 `fccb0a8435645b2ac9b284fc3ba28f47084bdb60`에서 시작했다. 동일 Sites 프로젝트 `appgprj_6acb0edd32f08191ba25ad7cdd39fdbc`의 새 원격 변경 여부를 먼저 확인하고, 기존 공개 범위를 유지하여 OPS를 먼저 배포한다.

운영 배포 후 실제 예약을 저장하거나 문자를 보내는 검증은 하지 않는다. 필요한 테스트는 합성 데이터로 수행하고 운영에서는 읽기 전용 UI 확인만 한다.
