# BOATN OPS 예약 등록·변경·취소·복원 연동

## 사용 방법

1. 상담 상세 또는 관리자 직접 예약에서 확정한 날짜·시간·금액·장소를 입력합니다.
2. 출항 요트는 탑승 인원과 입금을 확인한 결제수단을 선택합니다.
3. 일정 협의·입금 확인 후 예약을 확정하면 OPS 등록 작업이 자동 시작됩니다.
4. 상세 화면의 BOATN OPS 상태에서 완료 여부를 확인합니다. 기존 충돌 건은 자동 재처리하지 않습니다.
5. 연결된 확정 예약은 목록 또는 상세 화면의 상태 메뉴에서 **취소**를 선택하고 확인합니다. OPS 취소가 확인되면 모먼트링크도 취소로 바뀝니다.
6. 취소된 예약의 **예약 복원 → 복원 확인**을 누르면 원래 날짜·시간의 동일 OPS 예약을 복원합니다. OPS 확인 후 모먼트링크도 **확정**으로 돌아옵니다. 휴지통의 상담 복원과는 별도 기능입니다.
7. OPS에서 연결된 예약의 날짜·시간을 바꾸거나 취소·복원해도 모먼트링크에 자동 반영됩니다. 서버는 OPS 저장 후 전달을 시작하며, 열어둔 목록·상세는 기존 30초 확인 주기에 갱신합니다. 작성 중인 메모·문자·상태 입력이 있으면 화면 교체를 미룹니다.

## 등록 범위

- 클래식 → 레오파드 요트, 프리미엄 → 11호(메가), 시그니처 → 리파리. 출항형 라이트·올인원만 자동 연결합니다.
- 정박 상품은 실제 운항 요트를 지정해야 하므로 OPS에서 직접 등록합니다. 출장·트렁크·헬기는 OPS 요트 예약에 등록하지 않습니다.
- 기존 확정 건을 일괄 소급 등록하지 않습니다.
- OPS 등록 완료 후 날짜·시간을 바꾸고 일정·입금 확인 후 **수정·확정**을 누르면 같은 OPS 예약에 자동 반영됩니다. OPS가 저장을 확인한 뒤 모먼트링크의 확정 일정과 문자 초안을 갱신합니다. 기존 금액·장소·인원·결제수단은 유지합니다.
- 취소는 연결된 동일 OPS 예약의 기존 취소 처리 경로를 사용합니다. 날짜·시간과 변경 버전을 확인하며 승선 완료 건이나 미완료·충돌 상태의 연동 작업은 자동 취소하지 않습니다. 취소 확인 전에는 기존 확정 상태를 유지하고 문자 준비·상태 변경·휴지통 이동을 막습니다.
- 취소 요청은 고정 요청 ID로 최대 2회 전송합니다. 응답 유실 시 처리 결과를 먼저 조회하며, 2회 이후에는 결과 조회만 허용합니다. OPS에서 취소 후 복원되거나 일정이 다시 변경된 경우 자동으로 재취소하지 않습니다. 기존 충돌 건은 수정하거나 재시도하지 않습니다.
- 취소해도 금액·입금·결제수단·고객 정보는 보존합니다. 환불 완료로 처리하거나 취소 문자를 자동 발송하지 않습니다. 환불은 담당자가 별도로 확인합니다.
- 복원은 기존 OPS 복원 경로의 정원·일정·원본·출항 기록 및 동시 변경 검사를 유지합니다. 기존 연동 충돌·처리 중인 캘린더 변경·승선 완료·노쇼·일정 변경 건은 자동 복원하지 않습니다. OPS 확인 전에는 취소 상태를 유지하며 금액·입금·문자 이력은 그대로 보존합니다.
- 복원 요청도 고정 요청 ID로 최대 2회 시도하고 이후에는 처리 결과만 조회합니다. 복원 후 OPS에서 다시 취소된 예약을 같은 요청으로 재복원하지 않습니다. 취소→복원→재취소에는 각각 별도 요청 ID와 이력을 사용하고 새 예약을 생성하지 않습니다.
- 변경 요청은 고정 요청 ID로 저장하고 응답 유실 시 먼저 처리 결과를 조회합니다. 최대 2회 자동 시도 후에는 조회로 결과만 확인합니다. 일정 충돌은 자동 재시도하지 않으며 기존 충돌 건을 일괄 변경하지 않습니다. OPS 실패·결과 미확인 중에는 기존 확정 일정이 유지되고 문자 준비를 막습니다.
- OPS 예약 저장과 구글캘린더 반영은 구분합니다. 기존 OPS 일정 변경 큐와 원자적 동시 변경·운항·정원 검증을 사용하며 캘린더 반영 상태는 OPS에서 확인합니다.
- 자동 문자 발송은 활성화하지 않습니다.

## 최초 OPS 등록 실패 후 새 날짜로 수정

- 최초 등록이 일정 충돌/일정 확인 필요로 거절되고 OPS 예약번호가 없는 경우, 직원이 다른 날짜·시간을 선택해 **수정·확정**하면 새 일정으로 등록을 확인합니다. 금액·장소·인원·결제수단은 유지합니다.
- 이전 실패 일정·오류·시도 횟수는 감사 이력과 등록 이력에 보존합니다. 같은 실패 일정을 반복 등록하지 않으며 다른 예약의 기존 충돌은 건드리지 않습니다. 조회나 상태 확인 버튼으로 충돌을 자동 재시도하지 않습니다.
- 새 일정의 OPS 등록이 확인된 뒤 모먼트링크의 확정 일정·문자 초안을 원자적으로 갱신합니다. 완료 전에는 기존 일정이 유지되고 변경 문자 준비를 막습니다. 고정 참조와 원래 입력값 검사로 중복 생성과 다른 OPS 예약의 잘못된 연결을 막습니다.
- 최초 등록과 새 일정 등록도 자동 시도는 최대 2회입니다. 이후에는 기존 등록 결과만 조회하며 세 번째 등록 요청을 보내지 않습니다.
- 오류 패널에는 실제 검사한 등록 요청 날짜를 표시합니다. 편집 중인 날짜를 이미 검사한 것으로 표시하지 않으며 새 일정 확인 버튼을 숨기지 않습니다.
- 검증: 전체 106개 테스트와 빌드 통과. 합성 11월 6일 20시 등록 실패→13일 20시 수정·확정→등록 1회 완료, 별도 충돌 보존, 응답 유실·동시 저장·원자적 롤백·최대 2회 제한과 9개 화면 크기를 확인했습니다.

## OPS → 모먼트링크 자동 반영

- 새 OPS 직원 변경만 대상으로 하며, 배포 전 기록을 일괄 소급하거나 기존 충돌 건을 재처리하지 않습니다. 기존 모먼트링크 참조가 있는 동일 예약에만 연결합니다.
- OPS 예약 저장과 전송 대기는 같은 트랜잭션으로 기록합니다. 모먼트링크가 보낸 변경은 다시 전송하지 않습니다. 날짜·시간과 취소/복원 상태만 전달하며 고객 연락처·금액·메모·승선 정보는 보내지 않습니다.
- 기존 전용 연결 키에서 파생한 HMAC으로 시각·메서드·경로·본문을 검증합니다. 고정 이벤트 ID, 단조 증가 변경 번호, 변경 전 상태, DB 잠금과 처리 영수증으로 중복·역순·동시 변경을 보호합니다. 새로운 인증 키나 DB 스키마는 필요하지 않습니다.
- 변경 전달은 최대 2회입니다. 응답 유실 시 영수증을 먼저 조회하고 같은 이벤트를 재전달해도 한 번만 반영합니다. 두 번째 시도 중 중단되면 영수증 조회만 하며 세 번째 쓰기는 하지 않습니다. 실패·충돌이 남은 예약의 후속 이벤트는 앞선 결과를 건너뛰지 않습니다.
- 모먼트링크의 기존 충돌 건은 내용·시도 횟수·오류를 그대로 유지합니다. 진행 중인 발신 작업은 덮지 않습니다. 양쪽 변경 전 값이 다르면 새 확인 필요 상태로 멈추며 자동 등록/쓰기 재시도를 제공하지 않습니다.
- 확정 금액·입금 확인·장소·인원·고객 메모·문자 발송 이력은 유지합니다. 날짜·시간 변경 시 안내 초안은 새 일정으로 다시 만들고 이전 초안은 상담 보유기한 내 최근 8회까지 보존합니다. 문자는 자동 발송하지 않습니다.
- OPS의 Google 캘린더 반영 상태와 모먼트링크 반영은 별개입니다. 운영 예약을 검수 목적으로 변경하지 않습니다.
- 열린 목록·상담 상세는 약 30초마다 최신 상태를 확인합니다. 저장 전 메모나 편집 중인 내용이 있으면 화면 갱신을 미뤄 입력을 보호합니다.

## 일관성·복구

모멘트링크의 예약 확정과 연동 작업 생성은 같은 DB 트랜잭션입니다. 작업은 즉시 실행하고, 미완료 작업은 관리자 목록 갱신과 일일 정리 작업에서 제한적으로 재시도합니다. 고정 외부 참조로 먼저 기존 등록을 조회하여 통신 시간 초과 후 재시도에도 예약을 중복 생성하지 않습니다.

OPS는 기존 최신 캘린더 조회·운항 가능 여부·탑승 한도·결제수단·동시 변경 검사를 통과한 예약만 기존 원자적 등록 경로로 저장합니다. 캘린더 입력·예약·입금·감사 기록은 함께 저장하며, 조회가 불확실하면 등록을 중단합니다. 모멘트링크의 확정 여부와 OPS 등록 성공 여부는 별도로 표시합니다.

## 운영 환경 변수

OPS: MOMENT_LINK_ENABLED, MOMENT_LINK_TOKEN_HASH(SHA-256).
모멘트링크: OPS_WRITES_ENABLED, OPS_BOATN_CONTRACT_VERIFIED, OPS_BOATN_BASE_URL, OPS_BOATN_TOKEN(암호화 비밀값).
연동 주소: https://boarding.boatn.co.kr/api/integrations/moment/v1/
연결 키는 저장소에 기록하지 않습니다. 중지 시 OPS_WRITES_ENABLED=false 또는 MOMENT_LINK_ENABLED=false로 설정합니다.

## 검증 · 2026-11-05

모먼트링크 94개 테스트, OPS 3,069개 테스트와 양쪽 빌드가 통과했습니다. 합성 예약과 모의 OPS 어댑터로 목록에서 취소 → OPS 확인 → 취소 상태 및 상세 완료 표시를 검증했습니다. 중복·동시 요청, 응답 유실 복구, 최대 2회 제한, 기존 충돌 보존, 승선 완료·일정 변경·취소 후 복원 예약의 차단을 확인했습니다. 8개 화면 크기에서 가로 넘침 없이 완료 상태를 표시합니다. 운영 실예약을 테스트 목적으로 생성하거나 변경하지 않았습니다.

복원 추가 검증: 모먼트링크 전체 98개, OPS 전체 3,072개 테스트와 양쪽 빌드가 통과했습니다. OPS 복원 3개 집중 테스트에서 원자 저장·중복/동시 요청·금액/원본/토큰 보존·기존 충돌·승선/노쇼·운항 중복·저장 실패 롤백·다시 취소된 예약의 재복원 방지를 확인했습니다. 합성 브라우저에서 목록 복원 완료, 상세 미저장 메모 보호와 충돌 시 취소 상태 유지, 9개 화면 크기의 확인 영역과 44px 이상 조작 영역을 검증했습니다. 복원 확인창을 여는 동안 자동 새로고침이 중단되는 것도 테스트했습니다. 실제 고객·문자·환불은 테스트에 사용하지 않았습니다. 브라우저 크기 시뮬레이션이며 물리 기기 검수는 아닙니다.

역방향 추가 검증: 모먼트링크 전체 102개, OPS 전체 3,079개 테스트와 양쪽 빌드가 통과했습니다. 합성 예약의 실제 저장·변경 추적·전송 대기·HMAC 전송·수신 API를 연결해 시간 변경→취소→복원이 한 번씩 반영되는지 확인했습니다. 기존 충돌 예약은 새 변경 알림이 와도 기존 기록이 유지됐습니다. 동시 요청, 응답 유실, 최대 2회 전송, 두 번째 시도 중 중단, 원자적 롤백, 미저장 메모 보호와 9개 브라우저 크기의 가로 넘침 없음도 검증했습니다. 실제 고객 예약이나 문자 발송은 사용하지 않았습니다.
