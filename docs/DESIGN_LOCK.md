# 디자인·UI/UX 고정 명세

버전 2.0 / 기준: 2026-11-01 사용자 합의. 이 문서는 새로운 디자인을 자유롭게 제안하라는 요청이 아니다. 현재 미니멀 시안을 기능 개발 과정에서 훼손하지 않도록 하는 기준이다.

## 1. 시각 방향
흰 바탕, 아주 연한 회색 면, 짙은 회색 글자, 얇은 테두리와 작은 그림자. 여백·정렬·읽는 순서가 장식보다 우선이다. Apple의 고유 로고·전용 아이콘·폰트 파일은 배포하지 않는다. 기기의 시스템 폰트를 사용한다.

상품 포스터의 베이지/금색/핑크 배경, 리본, 하트 장식, 장식형 제목은 가져오지 않는다. 사용자가 올린 포스터는 가격과 이용조건의 **정보 출처**일 뿐이다. 이모티콘과 장식용 이모지는 넣지 않는다.

## 2. 기본 토큰
- 배경 `#F5F5F7`, 카드 `#FFFFFF`, 본문 `#1D1D1F`, 보조 문구 `#6E6E73`, 테두리 `#E5E5E9`.
- 버튼·입력 모서리 약 11–15px, 주요 카드 약 20–28px. 모든 컴포넌트가 동일한 토큰을 사용한다.
- 간격 체계 4/8/12/16/20/24/32px. 임의의 왼쪽 여백과 제각각인 카드 높이 금지.
- 본문은 원칙적으로 14–16px, 입력칸 16px. 가격은 18px 이상을 기본으로 한다. 보조 주석은 12px 기준. 금액을 무조건 작은 폰트로 줄여 해결하지 않는다.
- 주요 버튼 높이 48–50px 이상, 일반 터치 조작 44px 이상을 검수 목표로 사용한다.
- 제목은 자연스러운 의미 단위로 줄바꿈한다. 상품명·가격이 잘리는 경우 먼저 카드 배치와 너비를 변경한다.
- 금액은 `white-space: nowrap`과 숫자 정렬을 사용한다. 예: `1,090,000원` 전체가 한 덩어리여야 한다.

## 3. 반응형 원칙
기기 이름별 고정 이미지가 아니라 **실제 사용 가능한 CSS 너비**에 따라 배치한다. 회전 시 단순 확대가 아니라 카드 열 수, 글자 배치, 하단 버튼 위치가 바뀌어야 한다. 폴드 펼침·접힘·회전 중 선택 상품·희망 일정·입력값을 잃지 않는다.

- 좁은 화면: 상품 1열. 라이트/올인원 가격은 같은 카드 안의 비교 가능한 2열을 우선한다. 공간 부족 시 주중·주말 라벨을 가격 위에 배치한다.
- 헬기 3개 패키지: 휴대폰은 세로 카드 3개, 충분히 넓은 단일 상품 화면에서는 가로 3열. 109만원 금액이 잘려서는 안 된다.
- 중간 화면: 상품 수와 실제 카드 너비에 따라 1–2열. 사이드바를 억지로 유지하지 않는다.
- 넓은 화면: 내용 최대폭을 제한하고 중심 정렬. 과도하게 늘어난 긴 문장·거대 빈 공간 금지.
- 짧은 가로 화면: 고정 하단 버튼이 뷰포트를 잠식하지 않도록 문서 흐름 안으로 이동한다.
- 키보드가 나타나도 입력칸·오류 안내·제출 버튼에 접근 가능해야 한다. 임의의 강제 방향 잠금 금지.
- 안전영역은 `env(safe-area-inset-*)`, 필요 시 가변 뷰포트 단위를 활용한다. 내용 가리기와 화면 밖 가로 스크롤을 허용하지 않는다.

## 4. 고객 흐름 — 4단계
**상품 분야 → 같은 화면에서 상품 비교·선택 → 희망 일정 → 연락처·신청 완료.**

링크를 열면 카테고리 선택으로 바로 진입한다. 인사말만 있는 필수 시작 페이지, 불필요한 로그인, 앱 설치 요구를 만들지 않는다. 상품 선택마다 페이지를 여러 번 넘기지 않는다. 자세한 설명은 같은 화면 아코디언으로 펼친다.

### 상품 비교
첫눈에 보여야 하는 것: 상품명, 짧은 설명, 실제 상품 사진, 패키지명, 정확한 가격, 중요한 차이. 사진이 없으면 명시된 자리표시자를 쓴다. 임의의 인터넷 선박 사진을 운영 선박으로 보이게 하지 않는다.

요트의 세부 카드에는 라이트/올인원, 주중/주말, 총 이용시간/실운항시간을 표시한다. 꽃다발 조건은 올인원 카드에만 짧게 표시한다. 모호했던 별도 꽃다발 표는 삭제 상태로 유지한다.

출장은 동일 장식이라는 메시지를 먼저 보여주고 차이는 추가 서비스로 설명한다. 헬기는 촬영 원본과 편집본 유무를 한눈에 보이게 한다. ‘상담 후 추천’은 가격을 만들어 붙이지 않는다.

### 선택 상태
선택한 카드는 테두리와 선택 표시로 즉시 구분된다. 하단에는 상품명과 가격 요약, 하나의 다음 버튼을 표시한다. 카드 전체를 터치할 수 있어야 한다. 선택하면서 펼친 설명이나 스크롤 위치가 이유 없이 닫히거나 초기화되지 않는다.

### 일정
1순위 필수. 2순위는 ‘다른 희망 일정도 추가하기’로 접어 둔다. 추가하지 않은 고객에게 오류나 추가 클릭을 요구하지 않는다. 오전/오후/저녁/시간 무관 버튼과 선택적 정확한 시간 입력을 제공한다. 1·2순위가 동일 날짜여도 다른 시간이라면 허용한다.

### 연락처·완료
성함/휴대전화, 출장·트렁크일 때 희망 장소, 선택적 특이사항만 받는다. 선택 내용은 펼쳐 확인할 수 있게 하고 별도 중복 확인 페이지는 강제하지 않는다. 실제 운영에서는 서버의 접수 성공을 확인한 뒤에만 완료 화면을 표시한다.

고객 본인 문자 앱 열기는 **접수 후 선택 기능**이다. 문자 발송을 하지 않아도 접수된다. SMS 문구의 발화자는 고객이며 ‘위 내용으로 상담 부탁드립니다’로 마무리한다.

## 5. 관리자
고객 미니멀 화면과 관리자 작업 화면은 역할이 다르지만 간격·글꼴·버튼 체계는 공유한다. 모든 카테고리 상품/패키지 추가·편집·노출·정렬에 같은 편집 UX를 사용한다. 요트 3척을 코드 상수나 DB 제약으로 고정하지 않는다.

최종 운영판에는 인증 없는 고객/관리자 전환 탭을 제거한다. 시연판의 상단 전환 탭은 데모 전용이다.

## 6. 레이아웃 승인 조건
1. 가격·상품명·중요 조건이 잘리거나 말줄임표로 숨겨지지 않음.
2. 320px 너비에서도 전체 페이지 가로 스크롤 없음.
3. 가로로 돌린 뒤 상품/날짜/입력값 유지.
4. 키보드로 선택·이동 가능하고 선택 상태와 입력 오류를 색상만으로 구분하지 않음.
5. 확대/큰 글씨 설정에서도 의미 있는 재배치. 200% 텍스트 확대는 운영판 추가 검수 대상.
6. 버튼이 실제 터치 가능한 크기이며 고정 버튼이 마지막 입력·동의·가격을 가리지 않음.
7. 실기기 승인 없이 ‘모든 기기 완전 대응 완료’라고 보고하지 않음.
