# 러브헌터 상담 접수·월별 정산

새 상담에서 원문을 붙여넣으면 전화번호·성함을 추출합니다. 복수 번호는 고객 한 명을 선택하고, 성함이 없으면 상담 시작 후 추가할 수 있습니다. 상품·일정이 없어도 상담중으로 접수하며 예약 확정 전 상품을 선택해야 합니다.

원문은 직원 전용 상담 메모에만 저장합니다. 고객 문자·안내 링크·OPS·캘린더에는 전달하지 않습니다.

일반 문의는 50,000원, 출장 문의는 40,000원입니다. 예약 성사·취소와 관계없이 최초 접수월에 계상하고, 전화번호 정규화와 전역 UNIQUE 해시로 기간과 관계없이 최초 한 번만 청구합니다. 재전송·동시 접수는 중복 상담·수수료를 만들지 않습니다. 상담 보유기간 종료 후 재접수해도 기존 수수료만 유지합니다. 이후 상품 변경은 최초 접수 요금을 바꾸지 않습니다. 기존 예약을 소급 가져오거나 과금하지 않습니다.

관리자는 러브헌터 정산에서 월별 일반·출장 건수, 합계, 상담 상세를 확인합니다. 영구 중복 방지를 위한 전화번호 해시는 접근 제한된 식별 정보이며 익명 정보로 취급하지 않습니다.

## 배포

013_lovehunter_referrals.sql은 전용 수수료 테이블과 인덱스만 추가합니다. 기존 상담 FK는 삭제 시 NULL이 되어 수수료 이력을 보존합니다. 운영 빌드의 제한된 스키마 단계에 등록했고, 시드·상품·예약 데이터 일괄 변경은 활성화하지 않았습니다. 고객 데이터와 운영 인증정보는 소스에 포함하지 않습니다.

## 검수

클라우드의 PGlite 합성 데이터와 실제 HTTP·브라우저 흐름으로 확인했습니다. 최초 전체 검사 287개 중 252개 통과, 기존 VM 하네스에 새 모듈이 없던 35개 실패는 의존성 스텁 추가 후 관련 검사 46개 모두 통과했습니다. 문법 검사와 56파일 빌드도 통과했습니다.

브라우저에서 붙여넣기 → 상담 시작 → 직원 메모 → 성함 수정 → 상품 선택/예약사항 저장 → 중복 접수 차단 → 일반1+출장1=90,000원 월 집계를 확인했습니다. 360×800, 390×844, 884×1104, 1104×884, 1440×900 화면 크기에서 접수·정산 넘침과 브라우저/API 오류가 없었습니다. 실제 폴더블 기기의 물리 화면 검수는 아닙니다.

운영 배포 후 테스트 상담으로 재검수하며 실제 메시지·송금·기존 예약·OPS 충돌은 변경하지 않습니다.
