# 러브헌터 네이버 계약·정산

고객 네임카드 → **러브헌터 계약 · 네이버 결제** → 계약 정보 열기에서 계약 안내를 붙여넣고 **내용 수집·미리보기**를 누릅니다. 전화번호, 고객 결제금액, 리뷰 제공 수량을 확인하고 저장합니다. 다른 전화번호나 여러 전화번호를 포함한 원문은 저장하지 않습니다.

- 고객의 네이버 결제금액을 매출 기준으로 사용합니다.
- 공제액 = 고객 결제금액 × 6.5%, 원 단위 반올림.
- 471,000원 결제: 30,615원 공제, 440,385원 입금 예정.
- 기존 일반 50,000원 / 출장 40,000원 문의 수수료는 유지합니다. 계약 저장은 새 문의 수수료를 만들지 않습니다.
- 고객 결제 완료와 파트너의 실제 정산 입금은 별개입니다. 실제 입금액·입금일은 확인한 뒤 기록합니다.
- 원본 예약 총액·입금액·상태는 자동 변경하지 않습니다. 차이를 보여주고, 계약 저장 후 예약 금액·환불이 바뀌면 정산 재확인을 표시합니다.
- 매출과 6.5% 공제 비용은 행사월 기준입니다. 계약 정산 표의 실제 입금·미수는 고객 결제월 기준입니다.
- 계약 취소는 계약 정산 집계와 리뷰 제공을 제외하는 작업이며 예약 자체 취소나 실제 환불을 실행하지 않습니다.
- 리뷰 폭죽 300발 = 10개 = 1묶음(개당 30발). 무료 제공으로 OPS 준비 수량과 메모에 반영하며 예약 금액을 추가하지 않습니다.
- BOATN OPS 연결 완료 건만 독립적인 리뷰 이벤트 큐로 반영합니다. 기존 OPS 충돌 작업은 재시도·수정하지 않습니다. 실패는 2회까지만 시도하며 상태를 표시합니다.
- 계약 원문은 직원 전용 상담 메모에만 저장합니다. 고객 문자·안내 링크에는 넣지 않습니다. 문자·메일·송금을 실행하지 않습니다.

## 업데이트 내역

관리자 메뉴 **업데이트 내역**에서 현재 버전과 과거 운영 배포 기록을 검색할 수 있습니다. 새 버전은 해당 기기에서 한 번 자동 안내합니다. 고객 화면에서는 표시하지 않습니다.

과거 기록의 시간은 Vercel의 운영 배포 기록 생성 시각, 새 버전의 시간은 빌드 생성 시각과 최초 운영 조회 확인 시각을 구분합니다. 운영에서 실제 제공된 버전의 정보는 별도 이력 테이블에 보존합니다.

배포마다 `release-notes.json`의 버전·제목·변경 내용을 갱신합니다. 빌드가 Git 커밋과 생성 시각을 자동 기록합니다. 과거 이력은 수정·삭제하지 않습니다. 미완성 기능을 완료된 변경사항으로 기재하지 않습니다.
