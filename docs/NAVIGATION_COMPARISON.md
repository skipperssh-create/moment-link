# 단계 뒤로가기 및 제공사항 비교 · 2026-11-01

## 동작

- 서비스 선택 → 상품 → 일정 → 연락처 → 접수 완료 → 문자 미리보기 이동을 브라우저 방문 기록에 반영한다.
- 휴대폰·브라우저 뒤로가기와 화면 안의 이전 버튼은 같은 기록을 사용한다. 첫 서비스 선택 화면에서는 추가 기록을 만들거나 뒤로가기를 차단하지 않아 원래 방문 페이지로 나간다.
- 이전/다음 이동 시 상품·패키지·옵션·일정·연락처 입력을 메모리에서 유지한다. History에는 공개된 상품 선택과 단계만 저장하며 이름·전화·장소·요청사항·희망 날짜는 넣지 않는다.
- 새로고침 시 개인정보 복원 저장소를 만들지 않고 첫 화면으로 복귀한다. 새 상담도 이전 흐름의 기록을 정리한 첫 화면에서 시작한다.
- 접수 완료 후 이전 입력 화면으로 이동해도 중복 제출 버튼은 비활성화한다. 서버 응답은 제출 당시 상품·입력 스냅샷으로 완료 화면을 만든다.
- 각 상품 카드에 패키지별 제공사항 비교표를 펼친 상태로 제공한다. 총 이용시간·실운항시간, 확인된 제공항목, 추가 선택사항을 카탈로그에서 읽는다. 요트 올인원의 꽃다발 안내는 기존 선택 카드에 유지한다.
- 자료에 명시되지 않은 제공사항은 미포함으로 추정하지 않고 '상담 확인'으로 표시한다. 명시적으로 제외된 헬기 촬영 원본형의 편집본은 미포함으로 표시한다. 임의의 품목이나 가격을 추가하지 않는다.
- 기존 흰색·회색 디자인, 상품 사진, 패키지 선택 카드, 가격은 보존한다. 좁은 화면의 헬기 표는 제목과 긴 항목을 간결하게 표시하고 전체 명칭은 접근성 레이블 및 상세 안내에 남긴다.

## 검증

로컬 메모리 PostgreSQL과 실제 브라우저에서 다음을 실행했다. 운영 상담을 생성하지 않았다.

1. 연락처에서 뒤로가기 → 일정, 앞으로가기 → 연락처 입력 유지.
2. 화면 안의 이전 버튼 → 일정, 브라우저 뒤로가기 → 선택한 상품 유지 → 첫 화면 → 이전 문서로 이탈.
3. 일정 화면 새로고침 → 첫 화면 → 뒤로가기 한 번으로 이전 문서로 이탈.
4. 합성 접수 성공 → 뒤로가기에서 재접수 차단 → 앞으로가기 → 새 상담 → 첫 화면에서 이전 문서로 이탈.
5. 관리자 로그인 화면 진입 → 뒤로가기에서 이전 고객 단계 복원.
6. 요트/출장/헬기 × 320×740, 390×844, 844×390, 768×1024, 1024×768, 1440×1000 총 18개 브라우저 viewport에서 표 셀·가격 잘림 및 페이지 가로 넘침 없음. 정박형 표도 320px에서 시각 확인.
7. app.js 문법 검사, 정적 빌드 통과. 브라우저 오류 로그 없음.

증거: test-artifacts/navigation-comparison.json. 물리 Android 뒤로가기 버튼·iPhone 제스처·앱 내 웹뷰는 직접 검수하지 않았으며 브라우저 History 탐색으로 동작을 검증했다. 문자 실발송, 유료 서비스, 기존 OPS 변경 없음.
