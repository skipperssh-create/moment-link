# 새 상담 미확인 반복 알림

2026-11-15 사용자 요청. 운영 도메인: https://link.teamboatn.com

- 신규 고객 접수에 알림 기록을 만들고, 활성 관리자 기기로 즉시 Web Push를 요청한다. Neon `pushclock`의 `*/2 * * * *` 예약 실행이 확인되지 않은 접수를 다시 알린다. 첫 반복은 다음 2분 주기이며, 실제 도착 시간은 네트워크·휴대폰 정책에 따라 지연될 수 있다.
- 상담 상세를 인증된 화면에서 열어 표시한 뒤 별도 CSRF 보호 POST로 확인한다. 숨겨진 탭, 목록 조회, 자동 새로고침, 알림 쓸어 지우기는 확인이 아니다. 관리자 또는 해당 담당자(미배정이면 상담사)가 확인하면 팀의 반복을 멈춘다.
- 상태가 접수중에서 바뀌거나, 읽음·삭제·보관기간 만료이면 반복하지 않는다. 배포 이전 접수는 소급 등록하지 않는다. 예약·금액·담당·OPS 기록을 알림 확인 때문에 바꾸지 않는다.
- 알림별·기기별 원자적 발송 선점으로 겹친 실행을 막는다. 실패는 기기별 연속 2회로 제한하며 만료된 구독은 즉시 해제한다. 알림 연결 버튼을 직접 눌러 재연결하면 실패 제한을 초기화한다.
- 짧은 TTL 120초, 같은 상담의 push topic/tag, `renotify:true`, `silent:false`, 진동을 요청한다. 알림이 계속 쌓이지 않고 같은 알림을 갱신하면서 재알림한다. 백그라운드에서는 OS 기본 알림 소리를 쓰며, 강제로 무음·방해 금지·배터리 제한을 해제하거나 브랜드 음성을 재생할 수 없다.
- 푸시 연결이 없는 열린 화면은 미확인 접수에 2분 간격으로 기존 음성을 다시 재생한다. 브라우저 자동재생 제한은 실제 화면 터치로 해제한다.
- 별도 알림 테이블은 FK cascade로 개인정보 삭제와 함께 제거된다. 잠금화면에는 고객 이름·전화·예약 내용이 들어가지 않는다.
- 스케줄러는 인증된 Neon trigger만 받으며 DB/OPS 키를 사용하지 않는다. 전용 `PUSH_REPEAT_SECRET`으로 알림 전용 서버 경로만 호출한다. 기존 retention cron, OPS 작업, 요금제는 변경하지 않는다. Neon Free 프로젝트와 기존 Vercel Hobby 프로젝트를 재사용한다.

검증: 로컬 합성 DB/VM 전체 204개 검사 및 빌드 통과. 신규 접수→최초 발송→반복→확인 후 중단, 동시 실행, 권한·CSRF, 전송 실패 2회, 만료 기기, 폐기된 상담, 기존 예약/OPS 무변경, 실제 Neon의 위조 trigger 401 응답을 확인했다. 운영 배포 후 스케줄러 실행 기록은 별도로 확인한다. Work 로컬 브라우저 사용이 비활성화되어 실제 휴대폰 음량·백그라운드 수신은 미검증이다.

운영 중지: Neon에서 `moment-link-unread-2min` trigger를 disabled로 변경한다. 또는 기존 문자·알림의 관리자 PWA 푸시를 끈다. 기존 예약은 영향을 받지 않는다. 재활성화할 때 미확인 신규 접수만 다시 확인한다.
