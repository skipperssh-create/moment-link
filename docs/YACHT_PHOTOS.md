# 요트 사진 반영 · 2026-11-01

사용자가 제공한 클래식·프리미엄 전체 사진 ZIP의 8장을 보정하고 기존 상품에 게시했다. 외부 선박 사진은 사용하지 않았다.

## 적용

- CLASSIC: 일몰 외관 대표사진, 시설 4분할 상세사진 — 2장.
- PREMIUM: 선수 데크 대표사진, 실내 라운지, 프로포즈 장식, 실내 커플, 항해 외관, 야간 커플 — 6장.
- 대표사진 1600×900, 16:9. 상세사진은 가로·세로 원래 비율을 유지하고 너비에 맞춰 표시한다.
- 기존 색상·서체·가격·상품 구성은 유지했다. 사진 영역의 비율과 상세사진 사이 간격만 조정했으며, 상세사진을 펼칠 때 옆 카드를 불필요하게 늘이지 않는다.
- 커플 사진의 기존 얼굴 가림을 유지했다. 사진별 한국어 대체텍스트, 지연 로딩, 비동기 디코딩 적용.
- 운영 이미지 WebP 8장 합계 1,335,902바이트. 각 파일 1MB 미만. 운영 카탈로그 버전 4, 관리자 업로드 API와 게시 UI를 사용했다.
- 사진은 운영 DB 미디어에 저장되어 관리자 상품 관리에서 교체·정렬할 수 있다. 고객 화면은 기존 /api/media 경로로 읽는다.

## 보정 및 산출물

도구: built-in image_gen 편집 모드. 원본별로 자연스러운 노출·화이트밸런스·약한 노이즈 보정을 요청했다. 선박·시설·장식·인물·얼굴 가림 보존, 물체 추가·삭제 금지, 대표사진만 기존 내용 안에서 16:9 크롭이라는 조건을 사용했다. 이후 Sharp는 배포용 리사이즈와 WebP 인코딩에만 사용했다.

원본은 .local/photo-import-20261101/originals, 보정 PNG는 같은 경로의 edited 폴더에 별도로 보존했다. 최종 WebP는 output/yacht-photos, 다운로드 묶음은 output/yacht-photos-edited.zip이다. manifest.json에는 8장 각각의 전체 프롬프트, 원본 파일명, 최종 해상도·해시·공개 URL을 기록했다. 로컬 생성물은 Git 정적 배포에서 제외한다.

## 검증

로컬 관리자 API → PostgreSQL 미디어 저장 → 카탈로그 게시 → 고객 화면에서 8장 렌더링까지 확인했다. 320×740, 390×844, 844×390, 768×1024, 1024×768, 1440×1000 브라우저 크기에서 사진 로딩, 이미지 비율, 가로 넘침 없음, 가격 잘림 없음을 확인했다. 실제 물리 기기 검증은 아니다.

운영 공개 API로 카탈로그 4와 8개 미디어의 HTTP 200, WebP 형식, 예상 해상도를 확인했다. 게시 전후 모든 상품의 가격·구성·노출과 운영 설정이 같음을 비교했다. 로컬 증거는 test-artifacts/yacht-photo-responsive.json, .local/photo-import-20261101/production-receipt.json에 있다.

다른 상품의 미제공 사진은 기존 자리표시자를 유지한다. 이번 작업으로 SMS, 유료 서비스, 기존 OPS를 변경하지 않았다.
